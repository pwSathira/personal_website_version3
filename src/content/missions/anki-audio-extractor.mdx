I was building Mushoku, a site that teaches hiragana and katakana side by side the way English teaches lower and upper case, and it needed a native speaker saying every character. Plenty of Anki decks already had those recordings. Nothing would get them out.

## An Anki package is a zip with a lookup table

A legacy `.apkg` file is a zip archive. Its media are stored as `0`, `1`, `2` and so on, and a JSON file called `media` maps each number back to its real name. Reading that map restores the audio files’ original names. That was the starting point; current Anki packages also need a binary media map and decompression.

## Unsigned installers kept desktop users away

I had no code-signing certificates, so macOS and Windows both warned on first launch that the developer couldn't be verified. For a free tool from a stranger, that warning ends the install. I moved the same logic into an add-on that installs from AnkiWeb, where language learners already get their add-ons.

## Names that make sense outside Anki

Anki's media names tell me little in a music player. The exporter can name each file after a note field, or after several fields combined in a pattern.

    {

      kept: true,
    },
  ]}
  caption="An example vocabulary deck. HTML, sound tags and characters that file names can't hold are removed."

**Preview Names…** lists every new name before anything is written, and marks the files that would be numbered, skipped or replace an existing file.

## Support for current Anki packages

The first extractor only understood the older JSON media map. The add-on now reads both formats.
