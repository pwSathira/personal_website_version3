I was building Mushoku, a site that teaches hiragana and katakana side by side the way English teaches lower and upper case, and it needed a native speaker saying every character. Plenty of Anki decks already had those recordings. Nothing would get them out.

## An Anki package is a zip with a lookup table

A legacy `.apkg` file is a zip archive. Its media are stored as `0`, `1`, `2` and so on, and a JSON file called `media` maps each number back to its real name. Reading that map restores the audio files’ original names. That was the starting point; current Anki packages also need a binary media map and decompression.

## Unsigned installers kept desktop users away

The desktop app worked, but I didn't have code-signing certificates, so macOS and Windows both warn on first launch that the developer can't be verified. For a free tool from a stranger, that warning ends the install. I moved the same logic into a Python add-on that runs inside Anki and installs from AnkiWeb, where language learners already get their add-ons. The current repository focuses on the Anki add-on.

## Three ways to get the audio out

The add-on can read an `.apkg` or `.colpkg` without importing it into your collection, export a deck and its subdecks from the deck gear menu, or export selected cards from the Browser. Deck exports include cards currently in a filtered deck; deck and Browser exports read directly from Anki’s media folder.

## Names and ordering that make sense outside Anki

The original media name is useful to Anki, but a name like `sapi5js-42ecd8a4.mp3` tells me little in a music player. The exporter can name files after a note field or combine several fields with a pattern such as `{Word} ({Reading})`. HTML, sound tags and invalid filename characters are removed. If a chosen field is empty, the original filename is kept.

For notes with audio in several fields, I can keep word audio and leave example sentences out. Optional numbering follows card order, and deck names can become folders: `Japanese::Vocab` becomes `Japanese/Vocab/`.

Before writing anything, **Preview Names…** shows the resulting filenames and whether each file will be numbered, skipped or replace an existing file. Existing files can be skipped, overwritten or kept alongside a numbered copy. If two files in the same export receive the same name, the later one always gets a number.

## Take the study context with the files

An optional `audio_notes.csv` records the deck, note type, tags and plain-text fields behind each file. An `audio_playlist.m3u8` keeps the audio in card order without needing numbered filenames, with track titles taken from each note’s first field. That makes the export useful for listening outside Anki while keeping a route back to the original notes.

Reading and extraction run in the background, and export preferences are remembered. Deck and Browser exports also report audio that the cards reference but that is missing from the media folder.

## Support for current Anki packages

The first extractor only understood the older JSON media map. The current add-on also handles the binary media map and compressed files used by newer Anki exports.
