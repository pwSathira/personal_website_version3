I was building Mushoku, a site that teaches hiragana and katakana side by side the way English teaches lower and upper case, and it needed a native speaker saying every character. Plenty of Anki decks already had those recordings. Nothing would get them out.

## An Anki package is a zip with a lookup table

An `.apkg` file is a zip archive. Its media are stored as `0`, `1`, `2` and so on, and a JSON file called `media` maps each number back to its real name. The extractor reads that map and writes out every `.mp3`, `.ogg`, `.wav` or `.m4a` under its real name.

## Unsigned installers kept desktop users away

The desktop app worked, but I didn't have code-signing certificates, so macOS and Windows both warn on first launch that the developer can't be verified. For a free tool from a stranger, that warning ends the install. I moved the same logic into a Python add-on that runs inside Anki and installs from AnkiWeb, where language learners already get their add-ons. The desktop version stays on GitHub for anyone who wants it.

## Newer exports use a different media format

Anki 2.1.50 and later can export packages whose media map is binary and whose files are compressed. Both versions of the extractor read only the older JSON map.
